# Second hot paths

This file lists every place where the code keeps two instances or two copies of one piece of work for speed, with the
lane that keeps it and the size of the win. The lanes are the document build (`build`), the JSON walk (`validate` and
`build`), the dsv walk, the writers, and the kernel.

A row's reason comes from the code's comments and from measured runs of the bench. Where no run measured the win, the
row says so.

| What | Where | Lane | Why it is kept |
|---|---|---|---|
| The builder's hooks, one per build choice: facts or not, checked or not, refuse or not, keyless | `core/build/build.odin`, `builder_step` and the `builder_hook*` that store | build | Each build compiles out the fact branch, the capacity test, the duplicate-key test and the keyless rules it does not use. A run-time refuse test costs +6.1% instructions on citm, +6.5% on canada, +2.6% on logs and +1.8% on twitter, so a `Json` build that does not ask for it holds none of it. Jsonc and Json5 builds hold it and test a flag at each close. One facts hook for every JSON spec costs +3.2% to +10.1%, and running dsv's keyless hooks through a flag +2.6% to +8.5%. |
| `st_string` and `st_key_string`, `st_string_escaped` and `st_key_string_escaped`, `st_string_long` and `st_key_string_long`, `st_after` and `st_after_number` | `json/states.odin` | JSON walk | Not a speed choice. `#must_tail` needs a caller and its callee to have one procedure type, and a compile-time parameter of the state's own makes a second type, so a state that differs by one constant is written twice. `docs/walk.md` gives the rule and why a return would cost the stack at `-sanitize:address`. No measured reason recorded. |
| `number_h` and `number5_h`, each calling its reader with `$shape` true for a hook and false for `core.No_Hooks` | `json/scalars.odin` `number_h`, `json/json5.odin` `number5_h` | JSON walk, JSON5 build | A walk with no hook, which is `validate`, records no digit counts and no number shape. Merging the two into one run-time test cost the JSON5 build lane +6.5% on a copy of `logs.json` under a `.json5` name, before `logs.json5` existed. |
| `string_span_v2`, `string_span_v3` and `string_span_v4`, and `string_long`'s switch on `Walk.tier` | `json/strings.odin` | JSON walk | Each reader carries its x86 tier's target features, and `#must_tail` cannot jump between procedures built with different features. The switch runs once per walk, not per string. No measured reason recorded. |
| `lookup_v2`, `lookup_v3`, `lookup_v4`, `clmul_prefix_xor` and `masked_tail`, and the kernels that pick one with `when T == ...` | `core/kernel/amd64.odin`, `core/kernel/kernel.odin` | kernel | A tier's instructions are in a small procedure carrying the tier's features, which LLVM inlines into the caller's wrapper. A caller that is not inlined would otherwise fail to compile the tier's intrinsics. No measured reason recorded. |
| `pass_v2`, `pass_v3`, `pass_v4` and `pass_base`, each the same 64-byte block loop with its tier's features | `dsv/walk.odin` `run`, `dsv/pass.odin` `pass` | dsv walk | A block loop that calls kernels generic over `$T` must be built per tier for the kernels to use the tier's instructions. `run` switches on `kernel.tier()` once per walk. No measured reason recorded. |
| `pass` built with `$COMMENTS` true and false | `dsv/walk.odin` `run`, `dsv/pass.odin` `pass`, `dsv/records.odin` `read_cells` and `read_tokens` | dsv walk | A text with no comment byte compiles out the comment-line work: the mask that finds a comment line, its lines, and its tokens. No measured reason recorded. |
| `values_run` and `read_wide` built with `$KEYS` true and false | `dsv/records.odin` | dsv walk | A headed record emits its column's header cell before each cell and reads the header's cells by index. A headerless record emits no key and holds none of that code. No measured reason recorded. |
| `pass` built with `$EMIT` true for `walk` and false for `validate` | `dsv/walk.odin`, `dsv/pass.odin` | dsv walk, dsv validate | `validate` records no positions and no keys, so its instance holds no position code and no key buffer. No measured reason recorded. |
| `values_run` built with `$ESC` true and false | `dsv/records.odin` | dsv walk | A block with no backslash mask and no carry from the block before it starts no cell with an escape, so its run holds no escape test. No measured reason recorded. |
| `string_probe` beside `string_short` for keys | `json/strings.odin` | JSON walk | The probe runs more instructions, and takes less time because a predicted branch at the closing quote lets the next token start before the bytes arrive. Reading keys with `string_short` runs 3-16% fewer instructions and loses 7-52% of the wall: logs 33-42%, wide 38-52%, twitter 13-22%, citm 7-11%. |
| `subtree_step`, an out-of-line step over a subtree | `core/document.odin` | key | The call keeps the next member's address from waiting on the load of `n`. Inlined it runs 0.3-0.5% fewer instructions and loses wall on the key lane: wide 16%, twitter 7%, logs 3%, citm none. |
| `scan_step` instantiated apart in `scan_hook_many` and `many_step` | `core/build/many.odin` | several paths | A direct call in the document hook speeds several-path scans 12-20% and queries 8-12%, for 33 KB of text. The stream and replay sinks keep the shared `many_step`. |
| `colon_fast` beside `st_colon` | `json/states.odin` | JSON walk | Without it wide loses 20-26% and logs 3%. On `pretty.json` the build lane is within noise without it and runs 0.4% more instructions, since `": "` is a hit in both. |
| `st_member_run` beside `st_key` and `st_value` | `json/states.odin` | JSON walk | Without it wide loses 17-22% and logs up to 2%. `st_after_number` enters it only for a member flush against its comma: entering it on indented text cost `pretty.json` 3-8% and twitter 2-3.5%. Bypassing it for one member after it met a non-number value, with a flag in `Walk`, lost 1-6% on logs, wide, pretty, twitter, citm and nested. |
| `st_number_run` beside `st_value` | `json/states.odin` | JSON walk | Without it `pretty.json` builds 2.5% slower and citm 1.3%. Canada is even on `build`, and `validate` runs 1% more instructions. |
| `st_open_run` beside `st_value` | `json/states.odin` | JSON walk | Without it `deep.json` runs 42-51% more instructions. Every other lane is within 0.1%. |
| `indent_fast` beside `skip_indent` | `json/whitespace.odin` | JSON walk | Without the prediction indented text runs 28-52% more instructions. |
| `string_short`, `string_lean` and `string_escaped` beside `string_long` | `json/strings.odin` | JSON walk | Without `string_short` logs runs 5-7% more instructions, without `string_lean` longtext 8-14% and logs 5-7%, without `string_escaped` longtext 19-33% and escape 3-5%. |
| `json.number`'s fast arms beside `number_decimal` | `json/unescape.odin` | read | Without them canada read runs +59% instructions, wide +52%, logs +22%, citm +16%, twitter +5%. |
| `decode_block` beside `decode_scalar` | `json/unescape.odin` | read | Without it longtext read runs +577% instructions and utf8 +300%. |
| `json.text` beside `core.text` | `json/unescape.odin` | read | A compile-time caller inlines the decode. Going through `core.text` runs 0.4-1.1% more instructions on read lanes. |
| `EXP_SHIFT` beside `compute_exp_shift` | `core/spell/zmij.odin`, `core/spell/exp_shift.odin` | float text | A regular double reads its shift from a 2 KiB table, a power of two and a subnormal compute it. The table runs canada 8.7% faster, prices 5.5% and integral values 5.3%, and random bits are even. |
| `bytes_equal`'s 8-16 byte arm | `core/spell/text.odin` | key | Without it wide key runs 1.9% more instructions. Other key lanes are within 0.08%. |
| `plain_quoted` beside `decode_text`, read-time rather than walk-time | `dsv/document.odin` | read | Decoding every quoted cell runs +173% instructions on a fully quoted CSV. Deciding in the walk cost dsv builds 5-10%, so the test stays at the read. |
| The wide-count single slot beside `builder_counts` | `core/build/build.odin` | build | One giant container is the common case: without the slot wide build runs +27% instructions and table.csv build +30%. |
| `pass_v2`, `pass_v3`, `pass_v4` and `pass_base` take a second route for `build` with the default `Options` | `dsv/walk.odin` | dsv build | The route calls `pass` with literal options, which folds the header, delimiter and tolerance tests. A build whose options are literal at its only call site folds them already. A second call site with run-time options loses that, and `table.csv` builds 3.8% slower and `table.tsv` 9% slower without the route. With it they are within 1% and 1.5% of the single call site, for one more page of code. |
| dsv's sticky `quoted` flag in `pass` | `dsv/pass.odin` | dsv walk | Once a text has held a quote every block takes the quoted path. A per-block test wins 5-6% on a sparsely quoted text and loses 1-2% on `table.csv`, with no quote byte. It must also test `in_quote` and the closing carry. |
| `Walk` and every JSON state over `$S`, and `pass` over `$S` | `json/walk.odin`, `json/states.odin`, `dsv/walk.odin` | JSON walk, dsv walk | A call names one spec at compile time, so a build holds the code of the specs it names and no other. No measured reason recorded. |
| The JSON and dsv walks over `$H` and `$on` | `json/walk.odin`, `dsv/walk.odin` | JSON walk, dsv walk | The hook is a compile-time parameter, so its call inlines into the walk. A hook that tests a token's kind and returns folds into the walk, and `core.no_hook` compiles to no call. No measured reason recorded. |
| `on_token` and `on_token_spelled`, the typed read's hook bare and with the JSON5 number branch | `core/typed/read.odin` | typed read | A JSON or JSONC read has no spelled numbers, so its hook holds no test for them. Not measured apart. |
| `on_cell`'s reads of `.I64`, `.F64`, `.String` and `.Bool` beside `read_cell` | `dsv/typed.odin` | typed read | A cell of those kinds reads in the hook, with no call. They are what a table holds, and the hook is inlined at each of the walk's cell sites. No run measured the two apart. |
| The `H == Cells` arms of the walk, which keep a `""` mask and `SPELLING_DOUBLED` | `dsv/pass.odin`, `dsv/records.odin` | typed read | A quoted cell with no `""` then takes its inner span with no scan. Rescanning each quoted cell was the largest cost of the text lane. Every other hook compiles the arms out. |
| `write_dense`, the compact write over the source's bytes, beside `rows_run`, with `dense_run_v2`, `dense_run_v3`, `dense_run_v4` and `dense_run_base` | `json/write_dense.odin`, `core/kernel/compress.odin` | document write | A source of dense tokens has many rows for its bytes, and the block path drops the blanks outside strings in 64-byte blocks. The route is a source under `DENSE_BYTES_PER_NODE_BLANK` (11) bytes per node, and one under `DENSE_BYTES_PER_NODE` (26) when `dense_sample` finds the blanks outside strings in the first 2 KB to be under a sixteenth of them. The rows win on compact text from about 30 bytes per node, and on indented text from about 11, where every block pays a compress, so the blank count in a sample decides where the bytes per node alone cannot. A source of 2 KB or less takes the dense path without a sample, whose cost it would not repay. A block copy of the clean blocks, a block by block shortcut for blocks with no blank and a skip of the escape mask on blocks with no backslash each won on blank-free text and lost on text that mixes blocks, which the branch cannot predict. The escape mask is instead skipped by run, `dense_run` built with and without it: a run without it stops at its first block with a backslash, and the next run takes the mask when this one met a backslash, so text that mixes them pays one stop per such stretch. The x86 tiers were not timed. |
| `write.walk` built four times, compact and pretty, with `put_plain` and `put_opted` | `core/write/marshal.odin`, `json/marshal.odin` | typed write | Compact text holds no indent code, and a call without `ascii` or `escape_html` holds no test of them, and strings stay in line. Not measured apart. |
| `put_short` and `put_string_mid` beside `put_mixed` | `json/put_string.odin` | string write | `put_short` writes a string under 16 bytes in line under the caller's reservation, from one 16-byte load at the string when `kernel.head16` finds that load inside the string's page, and from loads inside the string otherwise. `put_string_mid` copies a 16 byte or longer string in 16-byte blocks with an overlapping last store, until a block holds an escape or a byte past 0x7F. Without `put_string_mid`, so with every string of 16 bytes or more going to `put_mixed`, logs writes 18% slower, nested 37%, citm 25% and twitter 15%, and the escape lane is even. The one-load form against the loads inside the string writes typed logs about 6% faster, and `head16`'s page test falls back under the address sanitizer. |
| `wide_run` beside `put_mixed`'s 16-byte step, and its copies `wide_run_v2`, `wide_run_v3`, `wide_run_v4` and `wide_run_base` | `json/put_string.odin` | string write | A 64-byte block with no stop is copied whole and its UTF-8 checked with the block's high bytes. Without it longtext writes 17% slower and utf8 is even, and twitter writes 7% faster, so it trades twitter for the long lanes. The tiers carry their target features so the 64-lane tests use the tier's registers. The x86 tiers were not timed. |
| `ESC_SEQ`, 256 entries of the bytes a byte is written as | `json/put_string.odin` | string write | Each byte of an escaping block is one load, one 8-byte store and an add of the length. Four selects on the byte in place of the table write 2.5 times slower on `escape.json` and 20% slower on twitter. |
| `put_escaped` for `ascii`, `escape_del` and `escape_html`, built for each combination of the three options, and the row loop's own copy of the block test | `json/put_string.odin`, `json/write_document.odin` | string write, document write | The stops these options add (every rune past U+007F, `<>&`) make a block with no stop rarer than in the plain writer, so the writer tests a block at a time, copies a clean block whole and goes byte by byte through a dirty one. The row loop tests a string's blocks with the same stops held on `Emit`, so these options keep a document write in its rows and do not send each string to `put_string`. Not timed apart, since no bench lane writes with these options. |
| `rows_run` built twice, compact and pretty | `json/write_document.odin` | document write | Compact text holds no indent code. `rows_run` writes a row and its key's value in one step with no test of the output's room, since `rows` hands it chunks that the room holds (`ROW_ROOM_SHIFT`), and a close, the comma and the line before a row are one test of `c.end`, held at the chunk's end. Against the loop that tested room, ill-formed strings, the end and a long token on every row, pretty logs write 8.6 to 15 GB/s (instructions 26.4 to 17.6 million), twitter 13.3 to 20.4, citm 16.9 to 26.3, canada 8.3 to 9.2, `pretty.json` 8.1 to 11.0 and escape 4.9 to 6.4. Compact twitter and citm, which take the rows, write 31% and 13% faster. |
| `copy_token` always moves two blocks, then up to four more from both ends | `json/write_document.odin` | document write | A token of up to 32 bytes takes no branch, and one of 33 to 128 takes two branches whatever its length. Against a loop from 0, canada writes 17% faster and twitter 6%, and logs and pretty.json are even. A token past `TOKEN_LONG` leaves the loop for `copy_long` in `rows`, which copies it by the system's copy: utf8 and longtext write 2% to 5% faster than when `rare_row` copies them, with the loop's instructions unchanged. A call to the system's copy in `rows_run` itself writes them 14% faster, but writes pretty logs and citm 1% to 2% slower, with 2% to 3% more instructions. |
| The size hint of `write.init` | `core/write/out.odin`, `json/write_document.odin` | document write | A buffer output with no hint doubles from 4096 bytes. With the source's size as the hint `longtext.json` writes 2.8 times faster (14.6 to 41.6 GB/s, 371 to 195 million instructions) and `logs.json` 20% (4.75 to 5.71 GB/s, 2091 to 1916 million instructions). Pretty text takes the same. `twitter.json` and `citm_catalog.json` are even. |
| `scan_v2`, `scan_v3` and `scan_v4`, each the 64-byte `scan_op` of `index_byte`, `last_index_byte`, `quote_run` and `quote_cut` with its tier's features | `core/kernel/amd64.odin`, `core/kernel/kernel.odin` | records | The forward scan finds the end of a `.Lines` or `.Seq` record and the backward scan the end of a stream window's last whole record. `quote_run` counts a slice's strings and levels for `each` from both guesses of where it starts, and `quote_cut` finds the next cut at a record's level outside strings. The compares and the mask move are written on 64 lanes, so the copy that carries a tier's features uses its registers: four SSE, two AVX2, one AVX-512 with a mask register. The x86 tiers were not timed. |
| `kernel.any_lane16` beside `any_lane` | `core/kernel/arm64.odin`, `core/kernel/lanes64.odin` | kernel | `simd.reduce_or` on a 16-lane mask is a shuffle tree on x86, and `pmovmskb` is one instruction. On arm64 `umaxv` is the instruction `reduce_max` gives. Not timed on x86. |
| The next struct of a list takes its frame over in `walk` | `core/write/marshal.odin` | typed write | A push and a pop per element is the most a list of small structs pays per byte, so the close of a struct that is a list's element reuses the frame for the next one. Not measured apart. |
| `any_value` beside the frame loop | `core/write/marshal_rare.odin` | typed write | An `any` or a hook's stand-in that holds a nil or a scalar is written at once, and any other value enters its side plan, so the loop holds no case for them. A side plan is built once for a call and kept in `side`, in both the typed write and dsv's hooked cells (`side_plan`). Not measured apart. |
| `write_cell` in line, with `write_other` for the rest | `dsv/write.odin` | dsv write | The kinds a row is made of are written in line, and the other kinds go to `write_other`, whose frame is large: a call that pays for it on every number is slower than the number's own work. Not measured apart. |
| `put_plain_cell` beside `scan_text` and `put_guarded` | `dsv/write.odin`, `core/kernel/kernel.odin` | dsv write | A cell without a stop byte is copied while it is tested, each byte read once, a cell under 16 bytes by one `kernel.head16` load and a longer one in 16-byte blocks, the last overlapping the one before. A cell with a stop byte, or one that `head16` cannot load, takes `scan_text` and the cold `put_guarded`, which quotes or escapes it. Against testing a cell and then copying it, `text.csv` writes 12% faster, and the other dsv lanes are even or faster. |

A row that gives wall time was timed by interleaved runs. A row that gives instructions was not, and instructions can
point the wrong way: `string_probe` and `subtree_step` both run more instructions and take less time. The rows with no
measured reason are kept for target features, for a compile-time spec or hook, or because a `#must_tail` state cannot
take a parameter.
